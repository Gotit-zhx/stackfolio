## 让内容跟着代码一起审阅

这个站点使用 Contentlayer 读取 `data/blog/` 和 `data/projects/` 中的 MDX 文件。文章包含标题、日期、标签、摘要和草稿状态；项目还记录源码、截图、个人贡献和演示入口。

内容与页面组件分开后，写文章时不必修改 React 页面。Git 记录每次变更，构建阶段检查必需字段和 MDX 语法。

## 从浏览器准备草稿

个人管理台独立监听 `127.0.0.1:9090`，使用本机随机生成的访问码登录。在内容库打开文章或创建新稿，填写元数据与 Markdown 正文，先用阅读预览检查结构，再保存草稿。

保存直接写回仓库中的 MDX 文件；再次修改会先保留本地备份。多个编辑窗口同时保存时，旧版本会提示冲突，避免静默覆盖。

## 发布是一个明确动作

草稿使用 `draft: true`，不会出现在公开列表、正文路由、RSS、搜索索引和站点地图中。发布时需要再次确认，随后将状态改为 `false`。

开发模式会重新加载内容；如果主站通过 Docker Compose 运行，还需要执行 `./local-server/start.sh site` 重建站点，再检查浏览器中的实际页面。最后运行检查、提交 Git，并按 Gitflow 合入 `develop`。

## 公开内容与个人运维分开

项目截图应当是准备公开的素材。上传文件会进入 `public/projects/`，主站重建后可直接访问，因此草稿状态不能保护已上传的私密图片。

主机和容器资源指标只在认证后的个人管理台显示。公开 Next.js 站点不包含内容写入与监控 API；模型密钥、环境变量和应用日志也不通过管理台返回。MDX 具备代码表达能力，编辑权限只留给本人，不接受不可信作者投稿。
