# Stackfolio 云服务器选型与部署规划

调研日期：2026-10-31（Asia/Shanghai）。截至 2026-11-01，已购买阿里云 Ubuntu 24.04 服务器并将项目克隆至 `/srv/stackfolio`；域名和 ICP 备案尚未办理，当前目标为 SSH 隧道内的受限验收，不启用公网网站入口。

## 已确认的边界

- 主要访客：中国大陆。
- 服务器预算：月均不超过 50 元，即一年不超过 600 元；域名和 AI 模型调用另计。包年优惠需要一次支付年费。
- 尚无域名，希望先了解备案流程与时间，再决定购买。
- 项目仓库：<https://github.com/Gotit-zhx/stackfolio>，公开；默认分支 `develop`。`main` 保留可发布基线，不因日常上传而直接更新。
- 阿里云服务器：Ubuntu 24.04，约 1.6 GiB 内存、40 GiB 磁盘；已创建约 2 GiB swap。项目目录 `/srv/stackfolio`。服务器地址不写入公开仓库，连接时从本机安全配置读取。该实例的实际规格低于建议的 4 GiB 起步配置，需顺序启动并观察资源余量。
- 当前仅计划通过 SSH 隧道访问本机回环服务。未确认服务健康前，不视为已完成部署；不开放网站或演示公网入口。
- 两个演示项目源码由本人独立编写；其运行时克隆仍分别由各自仓库管理。
- 个人管理台仅本人使用，继续通过回环地址和 SSH 隧道访问。

## 初步选型建议

优先比较中国大陆地域的一台轻量应用服务器：**至少 2 核 CPU、4 GB 内存、60–80 GB SSD、公网 IPv4**。目标架构为 Linux x86_64；具体系统版本应选择 Docker 官方支持的长期支持版本。若 4 核 / 8 GB 套餐实际年费也不超过 600 元，可优先比较它的带宽、流量和续费成本。

暂不额外购买托管数据库、负载均衡、Kubernetes 或付费运维面板。AI 使用外部 API，不在这台小服务器部署大模型。

### 资源依据与限制

此前本地 Docker Desktop 单次低负载快照中，属于本项目的七个容器合计约 849 MiB：主站约 65、PostMaker 约 159、RSSHub 约 357、Redis 约 17、DataRadar 约 158、百草园 Caddy 约 34、百草园 Django 约 61 MiB。四舍五入的分项可能与合计略有差异。

这不包含 Linux 系统开销、构建峰值、并发访问和后续数据增长，也不是云服务器压力测试；不能据此推断 1 GB 或 2 GB 足够。先选 4 GB 起步，上线前在目标机器检查构建和运行内存，图片响应、磁盘占用与流量。顺序构建各应用；后续可迁移到 CI 构建镜像，降低小服务器构建压力。

## 域名和 ICP 备案

建议先选可备案的普通域名，并以本人证件完成实名认证；个人备案时，域名实名认证主体应与备案主体一致。域名实名信息同步通常需要等待约三天，腾讯云特别建议等信息入库后再提交。购买国内服务器前，先在服务商下单页面核实实例地域、包年包月时长和剩余有效期都符合备案要求；例如腾讯云文档说明按量实例不支持备案，包月实例需满足其规定的最短购买期和备案期有效期。

选域名时优先比较容易记忆和输入的 `.com` / `.cn`，查询实际可注册状态、首年价与续费价，并让注册商确认所选后缀可备案；不预设任何具体名称仍可注册。不需要分别给两个演示购买域名，使用同一根域名的子域名即可；实际服务内容仍应如实向接入商说明。

大致步骤：

1. 按本人实际身份证件、住所和服务器接入商选择备案省份；查看该省个人备案的地址、年龄及居住证明要求，不推定用户属地。
2. 购买同一服务商认可的中国大陆备案资源；域名选可备案后缀，用本人实名信息注册。
3. 等待域名实名信息同步，整理身份证件及服务商要求的其他材料，在云厂商 ICP 控制台填写个人主体与网站信息。
4. 接听服务商核验电话并修正初审意见；完成工信部短信核验；等待省通信管理局审批。
5. 获批后核对网站名称与网站内容，添加首页备案号及规定链接，再按适用要求完成公安联网备案。

办理时间可参考阿里云指引的 **约 3–22 个工作日**，此外再留域名实名认证同步、准备材料和修改退回的时间。腾讯云指引说明初审约 1–2 个工作日、管局审核不超过 20 个工作日；周末和法定节假日不算工作日。实际时长取决于资料、属地和管局，不能承诺具体完成日。阿里云文档说明其平台注册域名可直接提交，其他注册商域名通常需要等待 2–3 天入库；腾讯云则建议实名认证后等待至少约三天。应按最终接入商流程办理。首次备案在通过前不要把域名解析至大陆实例并对外提供服务。云机公网 IP 可用于 SSH/受限演练，网站保持非公开状态。

个人博客、作品集是否符合个人备案范围，要看实际服务内容、网站名称及属地规则。Stackfolio 本身是个人作品集，但百草园包含社区能力；规划是在服务商/备案审核确认前，关闭公开注册、用户发帖、评论及上传等写入入口，初期只开放经本人维护的介绍、博客与只读项目演示。**这是部署前待实现和验证的限制，不表示当前应用已经有完整的只读模式**；默认关闭注册不代表已有账号无法写入。若计划开放用户生成内容，先向接入商确认个人主体是否可承载，以及适用的审批、备案类型和运营要求，再决定实际开放范围。

阿里云指引另要求在网站对外提供访问之日起 30 日内办理公安联网备案；它与 ICP 备案是两个步骤，应在上线清单中分别跟踪。

官方依据：[个人网站备案快速入门（阿里云）](https://help.aliyun.com/zh/icp-filing/basic-icp-service/getting-started/quick-start-for-icp-filing-for-personal-websites)、[备案审核时长（腾讯云，2026-08-21 更新）](https://cloud.tencent.com/document/faq/243/19650)、[备案流程（腾讯云）](https://cloud.tencent.com/document/product/243/18909)、[备案域名要求（腾讯云）](https://cloud.tencent.com/document/product/243/18905)、[个人备案所需材料（腾讯云）](https://cloud.tencent.com/document/product/243/18913)、[可备案资源条件（腾讯云）](https://cloud.tencent.com/document/product/243/19631)。省份要求、备案资格和政策以提交时服务商与主管部门为准。

## 拟采用的部署架构

购买域名后使用同一根域名的三个入口，以下 `example.com` 只是占位符，不表示该域名可注册或已归本人所有。

```text
访客 HTTPS
    └── 公网 Caddy：80/443
         ├── example.com             → 127.0.0.1:3000   Stackfolio
         ├── postmaker.example.com   → 127.0.0.1:8787   PostMaker
         └── baicaoyuan.example.com  → 127.0.0.1:8088   百草园内部 HTTP 入口

本人 Mac ── SSH 隧道 ── 127.0.0.1:9090 个人管理台
```

建议公网 Caddy 作为宿主机服务运行，才能直接访问以上宿主机回环端口；如果以后改成 Caddy 容器，必须另行配置共享网络和服务名，不能照抄 `127.0.0.1` 作为跨容器地址。

保留三套独立 Compose project：`stackfolio-site`、`stackfolio-postmaker`、`stackfolio-baicaoyuan`，统一用根仓库脚本维护，数据卷继续隔离。`local-server/` 名称暂时保留，将来可在服务器 `/srv/stackfolio/` 中复用；当前脚本仍是本地配置，不能原样当作已完成的云部署方案。

### 云部署前的配置适配

| 范围       | 要做的调整与验收                                                                                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公网入口   | 新增公网 Caddy 配置和证书持久化；验证 DNS、证书签发、HTTPS 跳转和代理头；备案批准前只做受限验收                                                                                                                                        |
| 端口       | `BIND_ADDRESS=127.0.0.1` 保持回环；公网只开放 80/443，SSH 按实际管理方式限制；不开放 3000、8787、8088、8448、9090、Redis 或 Docker socket                                                                                              |
| 主站       | 设置三个真实 `NEXT_PUBLIC_*` HTTPS 地址，并重建主站；构建参数会写入页面，不能只改运行时环境变量                                                                                                                                        |
| 项目详情   | 仅在公网可访问并验收后将项目 `demoStatus` 从 `local` 改为 `live`，填写实际 HTTPS `demoUrl`                                                                                                                                             |
| PostMaker  | HTTPS 后将 `POSTMAKER_COOKIE_SECURE` 改为 `true`；检查 workspace 密钥、DataRadar 的 `ALLOWED_ORIGINS`、代理后的 Cookie 与会话；AI 配额独立控制                                                                                         |
| RSSHub     | 将当前 `latest` 固定为验收过的镜像版本或 digest；核对国内服务器对依赖源和抓取目标的可达性                                                                                                                                              |
| 百草园     | 核对 `PUBLIC_ORIGIN`、`DJANGO_ALLOWED_HOSTS`、CSRF 来源及双层代理后的 HTTPS 识别；外层和内层 Caddy 之间需明确受信代理及 `X-Forwarded-Proto` 传递，不能把外部 HTTPS 误判为 HTTP；内部 Caddy 使用 HTTP，不与外层 Caddy 抢占宿主机 80/443 |
| 账号和上传 | 公网演示先关闭注册、匿名写入与上传；是否开放登录、评论、发帖或采集，按服务商备案内容审核和实际权限设计逐项决定                                                                                                                         |
| 管理台     | 可选在服务器单独运行并配置进程守护；继续只监听 `127.0.0.1:9090`，不通过公网 Caddy 代理；内容与 Git 的维护顺序见下文                                                                                                                    |
| 架构和依赖 | Mac 的 ARM 镜像不能直接视为 x86_64 镜像；在目标架构构建或使用 Buildx/CI；云端实际验证 GitHub、镜像仓库及软件依赖下载，不使用来源不明的镜像代理                                                                                         |

服务器从公开 GitHub 仓库拉取时使用公开 HTTPS，不保存个人 GitHub token。应用模型密钥、数据库密码、管理台访问码及 `.env` 不进入 Git。两个演示应用的实际源码提交和镜像 digest 应记录在发布清单，避免每次部署浮动到未知版本。

## 发布、备份与回退

继续使用 Gitflow：`feature/*` → `develop` → `release/*` → `main` + 版本 tag。服务器生产部署以验收过的 tag 或明确提交为准，不自动跟随 `develop`。本次规划文档只合入 `develop`，不创建首次生产发布。

优先在 Mac 管理台编辑内容、提交并推送后部署，避免服务器工作区与 Git 分叉。若在云端管理台编辑，必须先检查差异、按 Gitflow 同步回仓库，再拉取更新；不使用强制 reset 覆盖未提交内容。管理台现有功能不会自动提交、推送或部署。

- 数据：备份百草园 SQLite/媒体卷、PostMaker 工作区数据和各应用必要配置；Redis 为缓存，不替代业务备份。
- 一致性：SQLite 使用数据库备份机制，或停止对应应用后备份；不在写入时仅复制数据库文件而忽略 WAL。上传文件与数据库的备份应协调进行。
- 离机：每日加密备份到独立位置，初期可由 Mac 定期拉取；建议先保留近 7 日和近 4 周版本。仅存在同一块云盘上的快照不是离机备份。
- 发布：变更前备份数据，记录三仓提交、镜像及配置版本，逐应用重建并检查健康状态；不要同时堆叠构建。
- 回退：保留上一版镜像和数据恢复点；数据库迁移前确认兼容性，不能假定换回旧代码就能恢复旧数据库。
- 恢复：首次公开前在临时卷演练恢复，检查登录、文章、上传图、演示链接和 HTTPS。备份包含 secrets，应限制访问并加密。

## 分阶段推进

1. **选型和备案准备**：核对个人账号可买套餐、续费、流量和备案资格；决定可注册域名和首年/续费支出，确认个人备案对应的内容范围。
2. **购买后适配和预演**：配置密钥登录、系统更新与防火墙；在新的 `feature/*` 中实现公网入口、云配置模板和部署检查；本地演练后推送。
3. **备案期间受限验收**：安装 Docker、拉取明确提交、顺序构建，做数据库恢复和端口检查；使用 SSH 隧道验收，不把未备案站点临时公开到大陆实例。
4. **批准后首次发布**：在 `release/*` 验收 DNS、HTTPS、页面、登录、备份与资源余量；完成发布合并和版本 tag，再将指定版本按备案批准范围公开；上线后复验并更新演示状态。
5. **运行成本复核**：观察真实流量和内存、设置费用提醒，临近续费时比较同机续费和可恢复迁移成本，避免把首购价误作长期成本。

当前待决事项是域名、备案主体资料/属地要求、具体地域和账号内订单；此文档不触发任何购买或付费云资源创建。
