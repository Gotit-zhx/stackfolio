## 4. 每次新增项目的内容约定

后续应用使用 Next.js App Router + TypeScript。项目和博客正文使用 Markdown 与 YAML frontmatter，个人资料集中维护；第一版不依赖数据库或 GitHub 在线请求渲染页面。

预期内容路径：

```text
content/
  profile.ts
  projects/
    postmaker.md
    baicaoyuan.md
  posts/
public/
  projects/
    postmaker/
    baicaoyuan/
```

本阶段的项目草稿放在 `docs/projects/`；应用初始化时迁移到 `content/projects/`，不要形成两个长期维护的副本。

每个项目的 frontmatter 字段：

| 字段                 | 用途                                             |
| -------------------- | ------------------------------------------------ |
| `slug`               | 唯一标识，与 `/projects/[slug]` 路径对应         |
| `title` / `summary`  | 标题与列表摘要                                   |
| `featured` / `order` | 是否首页精选与手动排序                           |
| `tags`               | 精选技术栈，避免罗列全部依赖                     |
| `repository`         | 源码链接；无可公开源码时可省略                   |
| `demo.status`        | `not-deployed`、`local`、`live` 或 `unavailable` |
| `demo.url`           | 仅 `live` 时填写真实可访问链接                   |
| `draft`              | 未完成或未获准公开的项目稿不进入站点             |

详情正文固定覆盖：问题与目标、核心流程、已核实的实现、个人负责范围、截图/证据、取舍与限制、体验方式。没有确认的职责或效果不得填成事实。

博客 frontmatter 至少包含 `title`、`slug`、`summary`、`date`、`tags`、`draft`。草稿不出现在列表、详情和站点地图；未知 slug 返回 404。文章代码块只展示文本，不执行来自 Markdown 的脚本。

## 5. 演示与部署约定

用户希望同一站点能方便进入两个演示。当前 MVP 使用独立本地端口（8787、8088），避免在未经适配前把两个应用强行挂到子路径；云端可使用独立子域名，或在完成路由前缀适配后再使用 `/demos/*`。

主站与演示保持独立进程/容器。主站读取项目内容中的演示地址，不把两个业务应用直接搬进 Next.js 页面，也不在第一阶段引入它们的数据库。

代码核对发现：

- PostMaker 工作台挂载 `/static`，接口使用 `/api/...`，子路径适配需同时核对前端请求、资源路径、认证 cookie 和 FastAPI 代理前缀。
- 百草园使用 `createWebHistory()`，Caddy 按根路径处理 `/api`、`/assets` 等；子路径适配需核对 Vue Router base、构建资源路径、API、媒体与深层路由刷新。

因此，当前先完成独立端口、隔离 Compose project 和持久化数据卷的本地验收。演示数据使用独立示例数据；主站和不同演示应用的 cookie、上传与存储分别隔离。AI 调用预算、凭据和可体验功能在演示阶段配置，不在当前阶段假定开放付费模型调用。

服务器购买留到本地网页与演示的资源需求可测量后决定，不在此时确定云厂商、规格或域名。
