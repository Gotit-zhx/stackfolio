# gotit-zhx.top 公网发布清单

这份清单用于 `gotit-zhx.top` 的公网发布准备。当前站点仍是 SSH 隧道受限部署；在 ICP 备案和 HTTPS 验收完成前，不启用下面的公网 Caddy 配置。

需要手动操作的详细步骤见 [公网访问操作手册](public-domain-activation.md)。

## 已确定的域名规划

| 用途            | 域名                                 |      后端回环端口 |
| --------------- | ------------------------------------ | ----------------: |
| Stackfolio 主站 | `gotit-zhx.top`、`www.gotit-zhx.top` |  `127.0.0.1:3000` |
| PostMaker 演示  | `postmaker.gotit-zhx.top`            | `127.0.0.1:18787` |
| 百草园演示      | `baicaoyuan.gotit-zhx.top`           | `127.0.0.1:18088` |
| 个人管理台      | 不配置公网域名                       |  `127.0.0.1:9090` |

## 需要用户准备或确认的材料

### 域名和 DNS

- 域名注册商和 DNS 控制台的登录权限。
- `gotit-zhx.top` 的实名认证状态，以及实名主体是否为本人。
- 是否允许使用阿里云 DNS 管理该域名；当前权威 NS 看起来属于阿里云 DNS，但应以域名控制台为准。
- 备案前暂不开放网站公网访问；DNS 记录可以先准备，正式切换前需要确认备案状态和安全组规则。

计划中的记录：

| 主机记录     | 类型       | 记录值                  |
| ------------ | ---------- | ----------------------- |
| `@`          | A          | `120.24.174.196`        |
| `www`        | A 或 CNAME | `120.24.174.196` 或 `@` |
| `postmaker`  | A 或 CNAME | `120.24.174.196` 或 `@` |
| `baicaoyuan` | A 或 CNAME | `120.24.174.196` 或 `@` |

不要把私有地址 `172.17.1.64` 写入公网 DNS。解析生效后，应从外部 DNS 查询确认记录，再继续 HTTPS 验收。

### ICP 备案

请在阿里云备案控制台确认以下信息：

- 备案主体姓名、身份证件、手机号、邮箱和通信地址。
- 域名实名主体与备案主体是否一致。
- 服务器实例地域、产品类型、有效期和备案服务码/备案资源资格。
- 网站名称、网站服务内容和网站负责人信息。
- 备案所需的证件照片、核验材料和短信核验手机。
- 所在省份个人备案对地址、居住证明或年龄等要求。

网站初期建议按“个人作品集、个人博客、项目演示”描述，并保持公开区域以本人维护的介绍、博客和只读演示为主。注册、匿名发帖、评论和上传等用户生成内容在备案范围确认前保持关闭。

### 公网配置和验收

- 确认服务器安全组只开放 `80/443` 和必要的 SSH 管理入口。
- 保持 `3000`、`18787`、`18088`、`9090`、Redis、数据库和 Docker socket 不对公网开放。
- 提供一个用于 Caddy ACME 证书通知的邮箱地址；该邮箱不是服务器登录凭据。
- 确认 PostMaker workspace secret、百草园 secret、数据库密码和管理台访问码已在服务器私有文件中生成，未提交 Git。
- 确认首批公网演示是否只读，以及是否接受国内抓取依赖和 AI 调用的额度限制。

## 实施顺序

1. 在域名控制台确认实名状态和 DNS 托管位置。
2. 整理 ICP 备案材料并提交备案；备案期间继续使用 SSH 隧道。
3. 备案通过后，添加上表中的 A/CNAME 记录并从外部 DNS 验证。
4. 在服务器安装或更新公网 Caddy 配置：`deploy/Caddyfile.gotit-zhx.top.example`。
5. 在本机按 `deploy/public-release.env.example` 的 HTTPS 地址重建 `linux/amd64` 主站镜像，服务器只加载镜像。
6. 逐项验证主站、两个演示、HTTPS、Cookie、CSRF、代理头、健康检查、备份和资源余量。
7. 通过 `release/*` 合并到 `main` 并创建版本 tag。
8. 公网验收通过后，才把项目演示状态从 `local` 改为 `live`。

## 当前不需要提供的内容

- 不需要把服务器密码、SSH 私钥、GitHub token 或应用 secret 发给我。
- 不需要把管理台访问码写入仓库或报告。
- 不需要把私有 IP 配置到域名解析。
