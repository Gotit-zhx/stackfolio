# 个人管理台与发布工作流

## 本地启动

在项目根目录安装锁定依赖（仓库自带 Yarn，无需全局安装）：

```bash
node .yarn/releases/yarn-3.6.1.cjs install --immutable
node .yarn/releases/yarn-3.6.1.cjs admin
```

打开 <http://127.0.0.1:9090>。首次启动会生成 192 位随机访问码，保存在 `.local-admin/access-code`（目录权限 700，文件权限 600）。在自己终端运行 `cat .local-admin/access-code` 读取并输入，勿截图分享或提交 Git。关闭终端中的服务使用 Ctrl+C。

管理台固定绑定 IPv4 回环地址，不能通过局域网 IP 访问。会话有效期八小时，采用 HttpOnly、SameSite=Strict Cookie；退出或重启管理台会使相应会话失效。开发阶段回环 HTTP 不使用 Secure Cookie；请勿把这个入口直接反向代理到公网。

如需更换访问码，停止管理台后将旧文件移到本机安全备份位置，再重新启动，管理台将生成新访问码。不要将访问码设置进 NEXT_PUBLIC 环境变量。

## 写文章与维护项目

1. 内容管理中选择“写一篇博客”或“添加项目案例”，也可以打开已有内容编辑。
2. 填写标题、英文 slug、摘要、标签和正文。项目另填 GitHub、演示状态、封面、截图、个人贡献。
3. 用“阅读预览”检查 Markdown；MDX 自定义组件需在站点中最终验收。
4. “保存草稿”直接写入 `data/blog/*.mdx` 或 `data/projects/*.mdx`，草稿不会进入公开内容面。项目支持上传 PNG、JPEG、WebP，单张上限 1.4MB；上传后需保存项目。
5. 点击“发布内容”，再确认公开。发布将 `draft` 改为 `false`，不会自动提交 Git 或推送远程。
6. 主站开发模式会自动刷新；若使用 Docker，运行 `./local-server/start.sh site` 重建容器才能更新浏览器中的生产站点。其他演示不受影响。
7. 本地预览正确后，运行 lint、typecheck、build、管理台与内容发布测试，按 Gitflow 提交并合入 develop。

保存前检查必需字段、日期、URL、图片是否存在和 MDX 语法。已存在文件必须携带当前版本号，多个标签页的旧版本保存会返回冲突；写入按队列串行执行、先备份再原子替换。浏览器关闭或切换页面时会提醒未保存的修改。

备份在 `.local-admin/backups/`，操作记录在 `.local-admin/audit.jsonl`，不保存正文、访问码或环境变量到审计记录。需要恢复时先停止管理台，再从备份复制对应 MDX 回原路径，检查构建后提交 Git。管理台不提供永久删除功能；删除内容请通过 Git 审阅。

MDX 是拥有代码表达能力的受信任作者格式，因此管理台仅允许本人使用，不接受匿名投稿或其他不可信作者内容。

## 私有与公开的边界

| 功能                                      | 公开站点 :3000               | 本人管理台 :9090     |
| ----------------------------------------- | ---------------------------- | -------------------- |
| 自我介绍、邮箱、GitHub                    | 公开                         | 可打开公开站点       |
| 已发布博客与项目、截图                    | 公开                         | 可编辑源文件         |
| 草稿正文、编辑与上传 API                  | 不提供                       | 访问码登录后可用     |
| 演示状态                                  | 仅“本地 / 公网 / 未部署”说明 | 当前项目容器实际状态 |
| CPU、内存、磁盘、容器用量                 | 不提供                       | 访问码登录后只读     |
| 环境变量、模型密钥、应用日志、Docker 控制 | 不提供                       | 也不通过管理台暴露   |

管理台独立于 Next.js，不随主站容器打包；`.dockerignore` 排除整个管理台和私有状态目录。公开站点不包含 `/admin` 和 `/api/admin/*` 实现，直接访问返回 404。管理台 API 拒绝错误 Host、跨 Origin、跨站请求和未认证调用；监控只筛选三组 `stackfolio-*` Compose 项目。

截图上传立即写入 `public/projects/`。其中的文件在主站下一次构建后可公开访问，即使关联文章仍是草稿。因此仅上传你打算公开的项目截图，不上传私密文件。

## 监控数据口径

- macOS：CPU、内存、磁盘和运行时间来自当前 Mac；容器指标来自 Docker Desktop 虚拟机，两者不应直接相加。
- Linux 云服务器：将来在服务器启动同一管理台后，主机指标才是该云主机资源。现在不会伪装成云数据。
- 监控每十秒采样，保留进程内最近六十次 CPU/内存历史；重启会清空，不是长期监控或告警平台。
- Docker 不可用会明确提示，不把缺失数据补成“健康”。不读取其他非 Stackfolio 容器的指标。
- 目前不提供容器重启、终端、日志或密钥编辑，避免从内容编辑界面扩大为远程操作入口。

## 将来迁移到云服务器

当前不进行云部署。未来主站和受限演示通过 Caddy 等公网 HTTPS 入口提供服务；管理台继续只监听服务器 `127.0.0.1:9090`，通过本人 SSH 隧道访问：

```bash
ssh -L 9090:127.0.0.1:9090 <账号>@<服务器地址>
```

浏览器仍访问本机 <http://127.0.0.1:9090>，在服务器安全终端读取服务端访问码。安全组不要开放 9090、Docker socket 或内部数据库端口。若以后需要多人或直接互联网管理入口，应单独设计 TLS、身份提供商、角色权限和审计，而不是放开此本地服务。

## 验证命令

```bash
node .yarn/releases/yarn-3.6.1.cjs lint
node .yarn/releases/yarn-3.6.1.cjs typecheck
node .yarn/releases/yarn-3.6.1.cjs build
node .yarn/releases/yarn-3.6.1.cjs test:admin
node .yarn/releases/yarn-3.6.1.cjs test:content
```

管理台测试覆盖：认证、会话退出、登录限速、Host/Origin/跨站限制、目录穿越与符号链接拒绝、草稿保存、发布、备份、版本冲突、图片类型验证及本地演示不能假标公网在线。

内容发布测试覆盖 RSS 的发布、改标签、撤稿、全部撤稿与重新发布，确保旧标签 feed 不残留撤回内容；并在隔离临时目录运行真实 Contentlayer 编译，验证草稿、发布、撤稿三个阶段的搜索与标签索引。索引、RSS 与 Docker 生产站点都在构建后生效。
